# FF14 Srank Desktop

当前工程版本：**v4.2.8**；桥接核心：**v1.4.8**。

## v4.2.8：四大区选择、桥接隔离与同步审计

### 大区与服务器选择

- 「同步数据」支持陆行鸟、莫古力、猫小胖、豆豆柴四个大区。新选一个大区时自动勾选该区全部子服务器；可逐台取消，不会误选其他大区。
- 再次选择已取消的大区时，默认重新勾选该区全部服务器；此前仍选中的其他大区及其手动服务器选择保留。
- 大区未选择时不发送同步请求；每个已选大区至少保留一台服务器。如不再需要该区，应取消整个大区。
- 「服务器总览」独立提供四个大区筛选。取消大区时，从桌面、平板、手机三套服务器偏好中删除该区服务器；允许全部大区取消，结果保持空，不自动回填默认项。
- 桌面/平板/手机的可见服务器数量上限只影响展示，不改后台大区订阅；服务端对服务器归属再次校验。

### 桥接进程与版本隔离

- 桌面端本地桥接端口由旧版 `8788` 改为 `8790`，避免复用旧工具或旧 CMD 桥接实例。
- 桌面启动时必须核对 `/health` 的 `bridgeVersion` 与预期 `1.4.8` 完全一致；旧版或未知进程不被误复用，界面明确提示版本不匹配。
- 新桥接使用 `bear-bridge-data-v2` 独立目录。首次启动把旧 `bear-bridge-data` 复制到新目录，原目录保留；新旧进程不再并发写同一份缓存。
- 同步状态显示桌面版本、桥接版本和端口，方便直接确认实际运行的版本。

### Bear API 与同步数据路径

1. 启动匿名会话：GET `https://tracker.beartoolkit.com/`，临时 Cookie / CSRF 只存在桥接进程内存。
2. 获取 S 怪资源：POST `/api/syncSession`，只保留 `DatabaseHunt` 中 `Rank=5` 定义和四大区服务器清单。
3. 每个大区分别批量请求 POST `/api/lastDeathTimers`，请求体为 `{ "QueryDeathTimers": [本区已选服务器], "RankType": "sRank" }`，Referer `/srank`。
4. 豆豆柴先读公开 Live 数据；无有效 S 怪记录时退回 Bear 批量接口。其他大区批量结果缺失的世界会按服务器逐台限速复核，不按「每只 S 怪 × 每个服务器」展开请求。
5. 每条记录校验 S 怪定义、服务器归属、Unix 时间、维护标记和 CD 资源；重复、过期、跨区及冲突记录不直接写入。

### CD 计算 / 缓存 / 监控室

- 正常窗口取该只 S 怪资源定义的 `RespawnTimer`；维护窗口取 `MaintTimer`。
- 进闸时间 = 击杀时间 + 当前模式 CD 下限；强制时间 = 击杀时间 + 当前模式 CD 上限。
- 缺失或非法维护标记、过期资源、未来击杀时间、无效时间窗和冲突来源均不能生成已核验 CD；不使用通用默认时长伪装成 Bear CD。
- 四个大区独立缓存、独立元数据、独立重试时间和隔离日志；未知或跨区记录拒绝写入。
- 同一击杀锚点但维护 / 正常时间窗变化时更新原记录 CD 元数据，不生成重复击杀行。
- 同步快照确认后重新投影到首页、新版监控室、旧版监控室和计算器；即使记录完全相同也会刷新绑定，但只在实质字段变化时写盘。

### 绝不再把 100% 当作数据成功

- 进度分母是实际选择的服务器数量：豆豆柴 5 台、陆行鸟 8 台、莫古力 8 台、猫小胖 7 台；不再出现 5 台 × S 怪数量的 90/90 计数。
- 100% 只代表已处理完请求目标，不代表接口有数据。
- 原始数组为空显示「接口无记录」；HTTP / 网络失败显示「读取失败」；raw>0 但 parsed=0 显示「校验异常」；有效但部分拒绝显示「部分通过」。空或失败结果不清空旧缓存，也不刷新最近成功时间。
- 每世界保留请求 API、Rank、请求服务器、HTTP 状态、Content-Type、返回顶层字段、响应样本和 raw / parsed / distinct / accepted / rejected / duplicate / isolated 数量；敏感的 Cookie、CSRF 不展示也不落盘。
- Bear 429 使用全局冷却；指定只读临时网络错误与 5xx 有限重试；上游写入类请求不会自动重发。
