# FF14 Srank Desktop

当前工程版本：**v4.2.3**（监控室同步修复、重复行合并与多路线读取；Windows 构建待验证）。

## v4.2.3 监控室同步修复

- 每次确认同步快照后都会重新推送首页绑定数据；即使没有新增击杀记录，也会刷新监控室和计算器快照。
- 监控室击杀锚点或 CD 状态改变时会持久化，不再只在目标列表结构变化时保存。
- S 怪名称匹配忽略空格、标点、全半角差异；例如“先驱勇士阿提卡斯”和“先驱勇士 阿提卡斯”会归一到同一正式词条。
- 同一服务器、同一版本内的规范化重复目标会合并，优先保留有效击杀锚点和 CD 状态。
- 不跨大区、服务器或版本合并；保留手动记录、手动 CD 覆盖与本地设置。

## v4.2.2 多路线读取

- 四大区最多 2 个大区并行同步，四套缓存与状态继续严格隔离。
- 主线路：Bear `/api/lastDeathTimers` 批量读取。
- 定向复核线路：对本地锚点冲突或临近进闸窗口的少量目标，调用 Bear `/api/huntInfo` 交叉核对；每区最多 5 个，逐条限速。
- 两路时间相差不超过 120 秒才标记交叉确认；发生冲突的记录写入大区独立隔离日志，不参与 CD 计算。
- 注意：两个端点都属于 Bear Tracker，不是两个独立第三方来源。豆豆柴仍使用公开 Live 来源，不能宣称已有独立 Bear 双路验证。
- 所有并行任务共享 429 冷却控制，避免限流后继续加压。

## 下载与发布

Windows 安装版和 Portable 版需由 GitHub Actions 构建后发布至 [GitHub Releases](https://github.com/2077-SA/FF14-Srank-Desktop/releases)。当前源码测试通过不代表 EXE 已构建或线上 Bear 已实测。

发布步骤：将 `FF14_Srank_Desktop_v4.2.3_工程源码.zip` 上传到仓库根目录，打开 GitHub Actions，运行 **Build and publish FF14 Srank Desktop release**。

## 数据安全

四大区各自独立缓存、状态、重试与冲突隔离文件。无法确认的旧数据不会参与 CD 计算；Bear 远端失败不会清空本地缓存。
