# FF14 Srank Desktop

当前源码版本：**v4.2.4**（Bear CD 窗口贯通、监控室 CD 联动与桥接稳定性修复）。

## v4.2.4 重点修复

- 将 Bear 每只 S 怪的 `RespawnTimer` / `MaintTimer` 从最新资源定义计算出完整时间窗，并连同击杀锚点一起保存、传递。
- 正常状态使用 `RespawnTimer`；维护状态使用 `MaintTimer`。维护标记必须是明确布尔值，不猜测缺失状态。
- 进闸时间 = 击杀锚点 + Bear 最小 CD；强制时间 = 击杀锚点 + Bear 最大 CD。
- 同一击杀锚点下维护 / 正常窗口变化会更新原记录，不重复新增击杀历史。
- 新版、旧版监控室和计算器读取同一份经过校验的 Bear CD 数据。
- 未核验 CD 不回退到通用默认值。维护状态缺失、资源时间戳超过 6 小时、未来击杀时间或时间窗不一致时，监控室显示「CD 未核验」，不显示预计时间、不允许一键回填。
- 冲突隔离记录不覆盖最后一条可信记录；不同大区、服务器与版本不会互相合并。
- 同名怪空格、标点和全半角差异会归一化；仅在相同大区 / 服务器 / 版本范围内去重。
- Bear 只读请求临时网络错误和 5xx 最多重试两次；429 不重试，使用全局冷却；上游写入接口不会自动重发。
- S 怪时间资源每 6 小时重新核验；缓存投影 30 秒更新，活动 CD 窗口内计划约每 2 分钟检查一次。实际网络延迟受 Bear 服务与网络影响，不承诺秒级 SLA。

## 内部验证

- 桌面端 Node 测试：**26/26 通过**。
- 桥接端 Node 测试：**33/33 通过**。
- Chromium 端到端模拟使用实际 renderer 适配器和实际内嵌监控室，验证维护窗 50–80h、同锚点切换正常窗 84–132h、新锚点重算、重复快照、跨服隔离，以及维护标记缺失、资源过期、未来锚点、冲突可信级别的 fail-closed；无页面脚本错误。
- 自动化联测使用模拟 Bear / 本机桥接响应，不等于 Bear 在线 UI 实时逐只比对，也不等于 Windows EXE 实机测试。

## 发布

将 `FF14_Srank_Desktop_v4.2.4_工程源码.zip` 上传到仓库根目录，运行 GitHub Actions 中的 **Build and publish FF14 Srank Desktop release**。Actions 会先运行检查和测试，再构建 Windows 安装版与 Portable 版并发布到 [GitHub Releases](https://github.com/2077-SA/FF14-Srank-Desktop/releases)。
