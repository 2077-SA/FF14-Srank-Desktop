# FF14 Srank Desktop v4.2.2 更新笔记

## 多路线读取与交叉校验

- 四大区同步任务改为最多 2 个大区并行，任务队列、缓存、错误状态、最近成功时间仍按大区独立保存；不会跨区共享击杀锚点。
- 主线路使用 Bear `/api/lastDeathTimers` 批量读取 S 怪。
- 定向补充 / 复核线路使用 Bear `/api/huntInfo`：针对已有本地锚点的时间冲突、临近进闸窗口，或批量返回缺失但本地仍处于活动 CD 窗口的记录，按需复核或补充。
- 每个大区最多复核 5 个目标，逐条限速；不对全部服务器 × 全部 S 怪展开高频请求。
- 两路时间差不超过 120 秒才标记为交叉确认；与旧可信锚点一致但批量返回冲突，或两条路线彼此冲突时，写入该大区独立 quarantine JSONL，不参与 CD 更新。
- 未完成第二线路复核的数据标记为单源校验；无法解析的第二线路响应不会被当成确认。
- 明确来源边界：`lastDeathTimers` 和 `huntInfo` 都属于 Bear Tracker，不是两个独立第三方来源。豆豆柴继续使用公开 Live 来源，尚未完成外部独立来源验证。
- 四大区最多 2 个任务并行；共享 429 冷却，任何线路遇到限流后其他 worker 也会等待。
- 同步控制中心显示当前并行大区、交叉确认、单源校验、冲突隔离数量。

## 数据隔离与保护

- 四大区各自独立缓存、元数据、重试和下次检查时间。
- 服务器归属不匹配、未知世界、非 Rank=5 和无效时间继续拒绝写入。
- 冲突记录写入所属大区隔离文件，不覆盖旧可信缓存。
- 继续保留 v4.2.1 的同步控制中心、新旧监控室 / 计算器联动、30 秒本地快照、15 秒静默自动保存、排车 / OCR 默认折叠菜单。
