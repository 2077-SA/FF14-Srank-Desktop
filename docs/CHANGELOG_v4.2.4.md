# FF14 Srank Desktop v4.2.4 更新笔记

## Bear CD 联动与稳定性修复

1. Bear 每只 S 怪的 `RespawnTimer` / `MaintTimer` 被桥接到监控室与计算器。
2. 正常状态使用 `RespawnTimer`，维护状态使用 `MaintTimer`，维护字段缺失或不可识别时不做默认推断。
3. 同一击杀锚点切换维护 / 正常窗口时更新 CD 元数据，不新增重复记录。
4. Bear 时间资源每 6 小时重新核验；超时记录在监控室与计算器显示「CD 未核验」。
5. 未来击杀锚点、窗口时间与锚点不一致、超出 500 小时合理上限时拒绝产生预计时间。
6. 已隔离冲突不会覆盖最后一条可信记录；跨大区、服务器、版本互不合并。
7. 未核验 Bear 数据不会回退默认 CD，不展示预计进闸 / 强制时间，也不能一键回填。
8. 只读请求临时网络错误和 5xx 最多重试两次；429 全局冷却、不重试；上游写入请求不自动重发。
9. 维护状态缺失、资源过期、未来时间等风险都在监控室以「CD 未核验」显示，并暂停计算。
10. 缓存投影 30 秒；活动窗口内约 2 分钟检查；准确准点受网络和上游响应影响。

## 自动化测试

- 桌面端：26/26 通过。
- 桥接端：33/33 通过。
- Chromium 实际 renderer 适配器 + 内嵌监控室端到端模拟通过；涵盖维护 / 正常窗口切换、新锚点、重复快照、跨服隔离、过期资源、缺失维护状态、未来锚点和伪造冲突可信级别。无页面错误。

## 验证边界

联测使用模拟 Bear / 本机桥接响应，并非 Bear Timer 网页在线逐只对照，也不是 Windows EXE 实机运行。Bear Timer 页面当前通过浏览器页面抓取只返回 JavaScript 启用提示；最终线上相等性仍需在联网 Windows 桌面环境对照。远端轮询不是秒级 SLA。

桌面版本：4.2.4；桥接核心版本：1.4.4。
