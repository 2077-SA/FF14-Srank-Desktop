# FF14 Srank Desktop v4.2.1 更新笔记

## 核心：四大区数据物理隔离，防止 CD 污染

- 桥接数据从原先共享 state.json 改为四个独立数据分区：豆豆柴、陆行鸟、莫古力、猫小胖分别写入独立文件。
- 每条同步记录必须同时满足大区、子服务器、S 怪归属校验；任何世界与指定大区不匹配、未知世界或存在歧义的记录均拒绝写入。
- /hunts、/state 支持按 dataCenter 查询；单只查询接口会验证服务器归属，不允许跨大区读取。
- 同步调度按大区读取自己的缓存、计算自己的下一次检查时间，失败状态、最近成功时间、错误和下次检查时间独立保存。
- 事件记录附带 dataCenter，工具箱本地 Bear 记录也加入 dataCenter 字段；计算器按当前服务器所属大区查找击杀锚点，不跨区复用记录。
- 同一世界 / 同一 S 怪的覆盖键增加大区维度；保留手工记录，不会把其他大区的 Bear 记录当作当前记录删除。
- 旧版共享 state.json 首次升级时按已知世界归属自动迁移到四个分区。不能唯一判断归属的旧记录被隔离保存在 state-unassigned-v2.json，不参与 CD 计算，不会删除原文件。
- 未来新增世界可由 Bear 公开资源动态归属；如果同一世界被多个大区声明，则视为歧义并拒绝导入。

## 兼容与稳定性

- 桌面主程序版本：4.2.1；桥接核心版本：1.4.2。
- 保留 v4.2.0 的同步控制中心、四大区选择、真实进度、15 秒静默自动保存、30 秒缓存投影、计算器联动和排车 / OCR 折叠菜单。
- Bear 仍为匿名只读，不登录、不向上游写入。
- 本地测试：桌面端 14/14、桥接端 22/22 通过；JavaScript 语法检查通过。
- Windows 安装 / Portable 构建和真实 Bear 在线交叉验证需在 GitHub Actions 与 Windows 实机完成后确认。
